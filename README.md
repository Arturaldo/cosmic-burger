# Стартер на TypeScript для проекта Stellar Burger

Учебный проект «Космическая бургерная» (проектная работа 3-го спринта): конструктор бургера на React с состоянием в Redux Toolkit и RTK Query, перетаскиванием ингредиентов на react-dnd, маршрутизацией на react-router и авторизацией с обновлением токенов.

## Запуск проекта

1. Установите зависимости: `npm install`
2. Запустите dev-сервер: `npm run dev`
3. Сборка для production: `npm run build`

## Что реализовано в третьем спринте

- Страницы `/login`, `/register`, `/forgot-password`, `/reset-password`, `/profile` и `/profile/orders` (заглушка) на компонентах библиотеки `@krgaa/react-developer-burger-ui-components`.
- Маршрутизация на `<Routes>`, `<Route>`, `<Navigate>` с вложенными маршрутами профиля и `<Outlet />`.
- Защищённые маршруты: `/profile` и вложенные доступны только авторизованным (HOC-компонент `ProtectedRoute`); страницы входа и регистрации, наоборот, недоступны авторизованным.
- Возврат на запрошенный маршрут: неавторизованного пользователя с `/profile` перенаправляет на `/login`, а после успешного входа — обратно на `/profile`.
- `/reset-password` открыт только после ввода e-mail на `/forgot-password`.
- Клик по ингредиенту открывает модальное окно на маршруте `/ingredients/:id` поверх главной; прямой переход по этому адресу открывает отдельную страницу ингредиента.
- Заказы оформляют только авторизованные пользователи: с кнопки «Оформить заказ» неавторизованный попадает на `/login`.
- Токены хранятся в cookie. Запросы с accessToken идут с токеном в поле `authorization`; при ответе 401/403 пара токенов обновляется через `refreshToken` (POST `/auth/token`), и исходный запрос повторяется. Выход из системы выполняется по `refreshToken`.
- Профиль: данные пользователя подставляются в форму, при редактировании появляются кнопки «Отмена» и «Сохранить», на сервер уходит PATCH `/auth/user` только с изменёнными полями.

## Структура проекта

- `src/components` — компоненты приложения:
  - App, AppHeader, BurgerIngredients, IngredientCard, BurgerConstructor, ConstructorIngredient, Modal, ModalOverlay, OrderDetails, IngredientDetails — приложение и конструктор,
  - AuthLayout — общая разметка страниц авторизации,
  - ProtectedRoute — защита маршрутов (для авторизованных и, наоборот, только для неавторизованных),
  - ProfileMenu, ProfileForm — меню и форма редактирования профиля,
  - IngredientDetailsModal — модальное окно ингредиента на маршруте `/ingredients/:id`;
- `src/pages` — страницы: главная (`home`), вход, регистрация, восстановление и сброс пароля, профиль (`profile`, `profile-settings`, `profile-orders`), страница ингредиента, 404;
- `src/services` — Redux-хранилище:
  - `api.ts` — RTK Query API: ингредиенты, заказы и эндпоинты пользователя (регистрация, вход, выход, получение и обновление данных, восстановление пароля). Базовый запрос добавляет accessToken в заголовок `authorization`, при 401/403 обновляет токены через `refreshToken` и повторяет запрос,
  - `store.ts` / `root-reducer.ts` — стор и корневой редьюсер, к стору подключён усилитель `api.middleware`,
  - `hooks.ts` — типизированные `useAppDispatch` и `useAppSelector`,
  - `burger-constructor/` — слайс состава бургера и селекторы,
  - `ingredient-details/` — слайс выбранного ингредиента,
  - `order/` — слайс заказа,
  - `user/` — слайс пользователя (данные, статус проверки авторизации, факт запроса письма для сброса пароля), селекторы и экшен выхода из системы в отдельном файле `actions.ts`;
- `src/utils` — типы данных, константы (базовый URL API, имена cookie, типы drag-and-drop) и работа с cookie для токенов;
- `src/index.css` — общие стили проекта.

Данные приходят с `https://new-stellarburgers.education-services.ru/api`.

## Процедура создания коммита с проверками

При создании коммита автоматически запускаются проверка линтерами `stylelint`, `eslint` и форматирование `prettier`.

Если линтер обнаружит ошибки:

- Коммит создан не будет
- Необходимо исправить все выявленные проблемы
- Добавить исправленные файлы в индекс: `git add .`
- Повторить коммит

**Рекомендация:**
Для предотвращения ошибок на этапе коммита предварительно выполните:
`npm run lint`. Это позволит выявить и исправить проблемы до создания коммита.

Есть также команды для запуска проверок по отдельности:

- `npm run eslint` - запускает проверку линтера и исправляет проблемы, которые можно исправить автоматически,
- `npm run stylelint` - запускает проверку литера для файлов стилей и исправляет проблемы, которые можно исправить автоматически,
- `npm run prettier` - исправляет ошибки форматирования кода.

Можно добавить автозапуск этих команд при сохранении файла в вашей IDE.

Для создания коммита рекомендуется запускать команду `npm run commit`. Она позволяет обеспечить соответствие описаний коммитов [общепринятым соглашениям](https://www.conventionalcommits.org/en/v1.0.0/).

В проекте настроены алиасы, которые можно использовать при импорте модулей:

```
	alias: {
		'@': path.resolve(__dirname, './src'),
		'@components': path.resolve(__dirname, './src/components'),
		'@services': path.resolve(__dirname, './src/services'),
		'@pages': path.resolve(__dirname, './src/pages'),
		'@utils': path.resolve(__dirname, './src/utils'),
	},
```
